# 打包版验收清单

自动测试（`cargo test`、`npm test`）和浏览器预览覆盖不到的部分：需要真实账号、网络、
安装包或操作系统集成。每次发布前在**打包后的版本**上逐项走一遍，勾选并记下机器和版本。

## 0. 打包前

- [ ] 四处版本号一致：`Cargo.toml`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`、`package.json`，标签是 `v<版本>`。
- [ ] 仓库的 Actions Variables 里填了 `MC_LAUNCHER_CLIENT_ID`（Mojang AppID 审核通过后），构建日志里没有「MC_LAUNCHER_CLIENT_ID is not set」的警告。
- [ ] `Release` 工作流生成的草稿里有 Windows 安装包和免安装 exe、DMG、AppImage、deb、`latest.json` 和 `SHA256SUMS.txt`；文件名都不含空格。
- [ ] `latest.json` 里三个平台（`windows-x86_64` / `linux-x86_64` / `macos-aarch64`）都有条目，版本号一致，下载地址指向这个标签。
- [ ] 下载草稿里的安装包，用 `shasum -a 256`（Windows：`Get-FileHash`）核对与 `SHA256SUMS.txt` 一致。

## 1. 签名与系统提示

- [ ] macOS：配置了 `APPLE_SIGNING_IDENTITY` 时，`codesign -dv --verbose=4 "Islet.app"` 显示 Developer ID；公证后 `spctl -a -vv` 为 accepted，首次打开无「无法验证开发者」。
- [ ] Windows：配置了证书时，安装包和程序右键「属性 → 数字签名」能看到签名和时间戳；未签名时 SmartScreen 弹「已保护你的电脑」属预期。
- [ ] Linux：AppImage 有执行权限，双击或终端运行能启动。

## 2. 微软登录（内置客户端 ID）

- [ ] 新装状态下添加微软账号，不需要手动填客户端 ID。
- [ ] 浏览器授权完成后回到启动器，账号名、头像正确。
- [ ] 重启启动器后仍是登录状态（刷新令牌在系统钥匙串 / 凭据管理器里）。
- [ ] 用这个账号进一次正版服务器（或单人世界），不提示「无效会话」。

## 3. 皮肤与披风（3D 预览）

- [ ] 账号 → 皮肤：3D 人物显示真实皮肤，自动缓慢旋转。
- [ ] 拖动可以转，方向键可以转，双击恢复自动旋转；系统开了「减弱动态效果」时不自动转。
- [ ] 细手臂（Alex）皮肤手臂为 3 像素宽；旧版 64×32 皮肤左右手脚对称、无外套层。
- [ ] 有披风的账号在背后显示当前启用的披风；换披风后预览跟着变。
- [ ] 上传新皮肤后预览刷新，游戏里也生效。

## 4. 外置登录与 authlib-injector 缓存

- [ ] 添加外置（Yggdrasil）账号，首次启动时下载 authlib-injector，游戏内皮肤正常。
- [ ] 断网后再用同一账号启动：使用缓存的 authlib-injector，能正常进游戏（日志里有「keeping the cached one」或直接用缓存）。
- [ ] 联网时启动不会每次都重新下载（看下载进度或日志）。

## 5. 启动与退出后命令

- [ ] 实例设置 → 启动前命令：填 `echo pre > pre.txt`，启动后游戏目录里有 `pre.txt`。
- [ ] 退出后命令：填 `echo $MC_EXIT_CODE > exit.txt`（Windows：`echo %MC_EXIT_CODE% > exit.txt`），正常关闭游戏后 `exit.txt` 内容为 `0`；强制结束游戏时为非 0。
- [ ] 命令输出出现在游戏日志里；命令失败不影响启动器。
- [ ] 全局设置里填的命令在实例「继承」时生效，实例自己填了就用实例的。

## 6. 整合包

- [ ] 在线搜索整合包：加载器（Forge / NeoForge / Fabric / Quilt）和类型筛选能缩小结果；切到 CurseForge 后「优化」筛选自动去掉，「空岛」只在 CurseForge 出现。
- [ ] 安装一个 Modrinth 整合包、一个 CurseForge 整合包（后者需要 CurseForge API 密钥）。
- [ ] 整合包有新版本时实例上出现「有更新」，更新后模组列表变成新版，存档和自己加的设置保留。
- [ ] 导出为 CurseForge zip（需要密钥）：生成的 zip 能被 CurseForge App 或本启动器重新导入；导出为 Modrinth `.mrpack` 也能重新导入。

## 7. 世界、分组与收藏

- [ ] 收藏一个世界、建一个分组并把世界放进去；重启启动器后都还在。
- [ ] 旧版本留在本机的收藏（`mc-launcher.favorite-worlds`）在首次启动后迁移到世界上，迁移后不再重复。
- [ ] 「直接进入存档」从世界卡片启动后直接进入该世界。
- [ ] 截图页缩略图正常显示（`mcshot` 协议；Windows 上是 `http://mcshot.localhost`），点开是原图。

## 8. 自动更新

在旧版本上把 `MC_LAUNCHER_UPDATE_URL` 指向含新版本的 `latest.json`。

- [ ] 设置 → 检查更新：显示新版本号、更新说明和发布页链接。
- [ ] 下载进度正常；把 `latest.json` 里的 SHA-256 改错一位时，启动器拒绝安装并提示校验失败。
- [ ] macOS（DMG）：安装后自动重启为新版本；旧版保存为 `Islet.previous-*.app.backup`，新版启动约 60 秒后被清理。
- [ ] Windows（NSIS）：启动器退出并运行新安装包，装完后是新版本。便携版走的也是这个安装包（清单里只有一个 `windows-x86_64`），确认这符合预期。
- [ ] Linux（AppImage）：从 AppImage 运行时原地替换文件并重启为新版本，文件仍可执行；deb 安装或不是从 AppImage 运行时，下载校验后在文件夹中显示更新包。
- [ ] 更新后约 60 秒，缓存里旧的 `update-*` 目录和 `updates` 下的旧安装包被删除。
- [ ] 游戏或后台任务进行中点安装：提示先结束再更新。
- [ ] 断网时检查更新给出可读的错误，不卡住界面。

## 9. 语言与外观

- [ ] 设置里切换中文 / English / 跟随系统后重启，所有页面文字一致，没有混杂。
- [ ] 窗口缩到最小尺寸时布局不溢出；深色系统主题下颜色正常。

## 10. P2P 联机（两台机器，最好不在同一局域网）

- [ ] 第一次开房间时下载联机组件，进度条走完；中途点「取消」能停下，再开房间时重新下载并通过校验。
- [ ] Windows 第一次运行 easytier-core 时弹出防火墙提示，选「允许」后能连上；拒绝后诊断里显示节点或直连失败，不卡住界面。
- [ ] 房主：游戏里「对局域网开放」后，「重新检测」能找到世界并填好端口；没开放时给出提示，不让创建房间。
- [ ] 房主复制房间码，访客粘贴（带空格、小写、O/0 混写都能识别），访客在「多人游戏」里看到局域网世界并能进入。
- [ ] 访客也可以用「直接连接」输入页面上的 127.0.0.1 地址进入。
- [ ] 健康灯：连上后变绿；拔掉房主网线后几秒内变红，诊断列表指出是哪一项；恢复后回到绿色。
- [ ] 走中转的玩家显示「中转」和延迟，灯为黄色；直连的玩家显示「直连」。
- [ ] 侧栏小灯、状态栏「房间」段和联机页的灯颜色一致；点状态栏能回到联机页。
- [ ] 安全：访客电脑上开一个其他端口的服务，房主那边连不上（只开放游戏端口）。
- [ ] 退出房间、关闭启动器后，任务管理器 / 活动监视器里没有残留的 easytier-core 进程。
- [ ] 高级设置里换成自定义节点后能开房间；恢复默认后回到内置的 6 个。
- [ ] 日志在 `logs/easytier-host.log` / `logs/easytier-guest.log`，出错时页面上的提示能对上日志最后一条错误。
